# Архитектура Проекта

Этот документ представляет собой высокоуровневый обзор архитектуры проекта, предназначенный для того, чтобы помочь разработчикам понять его структуру и ключевые компоненты.

## 1. Обзор

Проект представляет собой систему управления фермой ботов, предназначенную для автоматизации задач на мобильных устройствах, вероятно, для социальных сетей или других приложений. Он включает в себя ядро для управления задачами и оборудованием, базу данных для хранения состояния, различные сервисы для специализированных функций (таких как ИИ и распознавание пользовательского интерфейса), а также интерфейс для администрирования.

## 2. Структура Директорий и Ключевые Компоненты

Ниже приведено описание основных директорий и их назначения.

### 2.1. `main.py`

Главная точка входа в приложение. Этот файл инициализирует и запускает основные компоненты системы.

### 2.2. `/core`

Сердце приложения. Здесь содержится центральная логика для оркестрации сервисов, управления задачами и взаимодействия с оборудованием.

-   `core.py`: Основное ядро приложения, отвечающее за начальную загрузку и управление жизненным циклом сервисов.
-   `dispatcher.py`: Направляет задачи или события соответствующим обработчикам или сервисам.
-   `service.py`: Определяет базовый класс или интерфейс для всех сервисов в системе.
-   `/hardware`: Управляет низкоуровневым взаимодействием с физическими или эмулируемыми устройствами.
    -   `adb_auto.py`: Обеспечивает связь с устройствами Android через Android Debug Bridge (ADB).
    -   `manager.py`: Высокоуровневый менеджер для операций с устройствами.
-   `/tasks`: Содержит логику для создания, постановки в очередь и выполнения задач.
    -   `queue.py`: Реализует очередь задач.
    -   `task.py`: Определяет структуру задачи.

### 2.3. `/db`

Обрабатывает все операции, связанные с базой данных, предоставляя слой абстракции для сохранения данных.

-   `connector.py`: Управляет соединением с базой данных.
-   `controller.py`: Предоставляет высокоуровневые функции для взаимодействия с базой данных (например, создание, чтение, обновление записей).
-   `/data`: Содержит модели данных (схемы) для таблиц базы данных, такие как `account.py`, `order.py` и `device_id.py`.

### 2.4. `/repository`

Реализует паттерн "Репозиторий", который предоставляет более объектно-ориентированный способ доступа к данным и отделяет логику базы данных от бизнес-логики.

-   `repository.py`: Основной класс репозитория, который предоставляет методы для доступа к данным.

### 2.5. `/services`

Содержит различные специализированные сервисы, которые предоставляют определенные функциональные возможности основному приложению.

-   `/ai_manager`: Управляет взаимодействием с большими языковыми моделями (LLM) и другими сервисами ИИ (Groq, Ollama, Hugging Face). Обрабатывает такие задачи, как генерация текста, управление историей и использование инструментов.
-   `/db_services`: Высокоуровневые сервисы, которые работают поверх контроллеров базы данных, управляя конкретными сущностями данных, такими как аккаунты и заказы.
-   `/panel_manager`: Взаимодействует с внешней панелью управления или API, вероятно, для получения задач или отправки отчетов о состоянии.
-   `/ui_recognizer`: Сложный сервис для распознавания и взаимодействия с элементами пользовательского интерфейса на экране устройства. Он использует как визуальный (`visual.py`), так и текстовый (OCR, `text.py`) анализ.

### 2.6. `/scripts`

Набор автономных скриптов для выполнения конкретных, часто ручных, задач. Они полезны для отладки, тестирования или выполнения определенных потоков автоматизации.

-   `control_script.py`: Скрипт управления общего назначения.
-   `login_script.py`, `posting_script.py`: Скрипты для конкретных автоматизированных действий.

### 2.7. `/views`

Содержит пользовательский интерфейс приложения, скорее всего, веб-панель администратора.

-   `app.py`: Основной файл приложения для веб-сервера (например, Flask или FastAPI).
-   `admin.py`: Определяет административный интерфейс и его представления.

### 2.8. `/meta`

Набор общих утилит, метаданных и сквозных функций, которые используются во всем проекте.

-   `enums.py`: Определяет общие перечисления (enums).
-   `schemas.py`: Содержит схемы для валидации данных (например, модели Pydantic).
-   `exceptions.py`: Определяет пользовательские типы исключений.

### 2.9. `/llm_data`

Хранит все данные, связанные с дообучением и работой больших языковых моделей.

-   `/datasets`: Необработанные и обработанные наборы данных для обучения.
-   `/adapters`: Дообученные адаптеры моделей (например, модели LoRA).
-   `/logs`: Логи обучения и контрольные точки.

## 3. Конфигурация

-   `core_configs.json`: Основной файл конфигурации для ядра приложения.
-   `.env`: Переменные окружения, такие как API-ключи и учетные данные для доступа к базе данных.
-   `requirements.txt`: Список всех зависимостей Python, необходимых для проекта.

## 4. Примерный Поток Данных

1.  **Менеджер Панели** или скрипт получает задачу (например, "опубликовать фото в аккаунте").
2.  Задача отправляется в **Диспетчер Ядра**.
3.  Диспетчер помещает задачу в **Очередь Задач**.
4.  Воркер забирает задачу и использует различные сервисы для ее выполнения:
    -   **Сервисы БД** извлекают учетные данные аккаунта и информацию об устройстве.
    -   **Менеджер Оборудования** использует ADB для управления указанным устройством.
    -   **Распознаватель UI** анализирует экран для поиска кнопок и полей ввода.
    -   **Менеджер ИИ** может использоваться для генерации подписи к посту.
5.  Выполняется логика скрипта (например, `posting_script.py`), который использует вышеуказанные сервисы для навигации по приложению и публикации фото.
6.  Результат выполнения задачи логируется и отправляется обратно.
